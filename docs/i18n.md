# Languages (EN, FR, DE, ES)

English stays at the existing URLs; French, German and Spanish live under `/fr`, `/de` and `/es`.
Every route sits under `app/[locale]` and is pre-rendered for all four languages; `next.config.ts`
rewrites unprefixed paths to `/en` internally and redirects `/en/...` back to the clean URL.

- **Copy stays in English in the source.** Components wrap visible text in `t()`, `tf()` (templates
  with `{0}` placeholders) or `tp()` (strings, lists and data objects). Translations live in
  `i18n/{fr,de,es}.json` as `{ "English text": "translation" }`. A missing key falls back to English.
- **Server components** read the dictionary from a per-request store set by `initLocale(params)`
  at the top of every page and layout. **Client components** get a small dictionary from
  `<LocaleProvider>` (only the strings client code can render, listed in `i18n/client-keys.json`).
- **Links** go through `@/components/i18n/Link` (and `lhref()` for plain `<a>`), which keep the
  current language. `usePathname`/`useRouter` come from `@/lib/i18n/navigation`.
- **Metadata**: `localizeMetadata()` translates titles and descriptions and adds canonical,
  hreflang (en, fr, de, es, x-default) and the Open Graph locale. The sitemap lists every language.

After changing copy, run `npm run i18n:extract` (rewrites `i18n/strings.json` and
`i18n/client-keys.json`), then add the new English strings to the three dictionaries.

## Things the extractor cannot see

- **Manual keys.** The extractor skips lowercase single words and strings without three letters in a row
  (`"way"`, `"policy"`, `"of 5"`, `"(required)"`, `"· by {0}"`, …), plus values of `value:`-style
  properties. Those keys were added to the three dictionaries by hand; `i18n:extract` never removes
  dictionary keys, so they stay. When a page shows a stray English word, add the key by hand.
- **Split headings.** Multi-line headings (`lines={tp(["Cookie", "policy"])}`, poster titles) are
  translated line by line, so the translations are balanced across lines ("Conditions de" /
  "réservation"). `SplitWords` no longer translates word by word: pass it translated lines or text.
- **Patterns.** Keys with `{0}` match any rendered string, longest literal first, and a pattern is
  ignored when its literal text is under 20% of the string (so `"{0} of {1}"` cannot swallow a
  sentence). Avoid composing copy from fragments; prefer `tf("Plan a {0} trip", name)`.
- **Ordinals** (`data/taxonomy.ts` `ordinal()`) follow the current language: 3rd / 3e / 3. / 3.ª.
- Not translated on purpose: place, stay and people names, schema.org `@type` values, CSS values,
  the postal address, and the team bios in `data/people.ts` (not rendered anywhere).
